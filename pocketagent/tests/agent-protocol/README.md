# Agent protocol fixtures

Run `tests/run-agent-protocol-tests.sh` with `POCKETAGENT_JSON_JAR` pointing to
JSON-Java 20250517 (`org.json:json:20250517`). The runner verifies the dependency's
SHA-256 before compiling. Android SDK stub methods are not used at runtime.

The schema in `schemas/codex-0.154.0/ThreadStartParams.json` was generated with
`codex app-server generate-json-schema` from the exact Codex 0.154.0 engine pinned
by the installer. It is an OpenAI Codex generated schema (Apache-2.0 project:
https://github.com/openai/codex). Version-specific wire schemas take precedence
over examples in documentation for newer versions.

`TurnStartParams.json` was generated by that same pinned engine.
`ModelListResponse.json` is its real unauthenticated `model/list` response, saved
without account data. The effort regression runs the production parameter builder
against these fixtures, including supported ranges, per-model reconciliation,
unknown metadata, and Auto resetting Codex's sticky effort to an advertised
default. Catalog examples are test data, not a promise of account entitlement.

`tests/run-usage-display-tests.sh` uses the same JSON dependency. It verifies
quota windows, unknown versus measured zero, active model buckets, explicit
provider restrictions, and thread-token/context separation. Its rolling event
fixtures follow pinned Codex 0.154.0 `AccountRateLimitsUpdatedNotification`:
the notification is sparse and does not include `ordinaryUsageAllowed`.
Production `RateLimitState` must preserve account restrictions and unrelated
buckets until an explicit provider update reports recovery; null values and
elapsed reset timestamps are not recovery signals.

The tests exercise the production session-parameter builder, JSONL envelopes,
multiline Unicode prompts, cancellation/error responses, shell argument quoting
through a real shell, project-component validation, identity-domain validation,
and model catalog variants. These host fixtures do not establish that PRoot,
provider account authentication or Android lifecycle behavior works on a phone.

The snapshot-delivery regression keeps the single agent worker inside an
installation while requiring two consecutive UI progress deliveries. It also
checks that coalesced progress uses the newest snapshot and an update arriving
during UI delivery is not lost.
